market_moving_events — architecture & data sources

Implementation notes for the scheduled market-moving-events dataset. Requirements: docs/idea.md · quick reference: README.md · code: scripts/save_market_moving_events.py + scripts/market_moving_events/
df_type market_moving_events output /Volumes/ssd/market_moving_events/YYYYMMDD.parquet calendar all_days runner save_data skill

1What the dataset is

One parquet per calendar day. Each row is one scheduled market-moving event occurring on that date — releases and index actions known ahead of time, never breaking news. The script is forward-runnable: for future dates it emits the expected schedule; re-running a past date fills in what actually happened.

columntypemeaning
timeDatetime(ns, America/New_York) event time (release time, or 16:00 close for rebalance-effective events)
symString stable event code, e.g. CPI, FOMC, SPY_REBAL_EFFECTIVE
event_nameString human-readable description, includes the scheduled clock time
release_forString? reference period of a release (May 2026, Q1 2026, claims week-ending date); null for index/FOMC events
event_date_typeString actual if time <= now when the row was built, else expected
summarizeString? what happened — only filled for actual rows
schedule_sourceString how the date was determined: official fred rule (§5)

Days with no events still get a file: an empty frame with the full schema, so multi-day scans concat cleanly.

Semantics to be aware of
  • actual vs expected is a snapshot at build time, decided per event by comparing the event's timestamp to the wall clock (ET). A file written at 07:00 for that same day says expected; rewriting it after the close flips rows to actual and fills summarize. The daily job should therefore run for a window like [today−3, today+N] so recent files get upgraded.
  • Re-runs are idempotent overwrites of the date's parquet.
  • Multiple events can share a timestamp (third Friday 16:00 holds SPY_REBAL_EFFECTIVE + TRIPLE_WITCHING, plus QQQ_RECON_EFFECTIVE in December); sym disambiguates.

2save_data interface integration

The script follows the save_data skill contract so the batch runner can drive it:

python scripts/save_market_moving_events.py --date YYYYMMDD --write [--data-dir BASE]
  • File name save_market_moving_events.py ⇒ df_type market_moving_events (the runner strips the save_ prefix).
  • Without --write it prints the frame and stops (interactive/debug use).
  • --data-dir BASE writes to BASE/market_moving_events/ instead of the registered path.
  • Exit code is the failure signal for the runner. Network problems never cause a nonzero exit (§8); only real bugs / write errors do.

Registration in cyc/cyc/files/df_types.yaml:

market_moving_events:
  cols:
    core: [sym, time]
  sym: sym
  time: time
  calendar: all_days
Why calendar: all_days (= every calendar day) With the default nyse calendar the runner would skip non-trading days, silently dropping events that fall on them — the Employment Situation has been released on Good Friday (market holiday), and MSCI announcements land at ~23:00 CET regardless of US sessions. Cost: ~365 small files per year, most empty.

Key pieces

  • base.Event — internal record produced by generators: dt (aware ET datetime), sym, name, release_for, schedule_source, summary_fallback (descriptive text used when no data summary is possible), and ref (a dict of context the summarizer needs, e.g. the reference month {"year": 2026, "month": 5} or the FOMC day2).
  • base calendar helpers — built on exchange_calendars XNYS with an explicitly extended horizon (today + 3 years; the library's default end is too short for forward runs): is_session, prev_session/next_session (walk to the nearest session), nth_weekday, last_weekday, nth_bday, last_bday. All "shift off a holiday" logic uses NYSE sessions as the proxy for business days. Known imperfection: NYSE trades on federal holidays like Veterans Day and Columbus Day, so federal-agency closures need special-casing where they matter (done for claims, §4).
  • Generators are date-filtered: each computes "does my event land exactly on d?" and returns [] otherwise, so a single day's build never scans ranges.

4Event catalog and scheduling logic

Times are ET. Holiday-shifted = moved to the previous NYSE session via prev_session.

Macro releases

symreleasetimedate logic
CPI fredrule Consumer Price Index (BLS), for the prior month08:30 FRED release id 10; fallback rule: first session on/after the 10th (real dates cluster 10th–15th; rule is ±1–3 days)
PPI fredrule Producer Price Index, final demand (BLS)08:30 FRED id 46; fallback: first session after the CPI rule date (PPI is adjacent to CPI in practice)
NFP fredrule Employment Situation (BLS)08:30 FRED id 50; fallback: third Friday after the reference week (the week containing the 12th of the reference month) — this is BLS's own scheduling convention and matches the published calendar almost always; the year-opening report slips +7 days when it would land Jan 1–5; holiday-shifted (e.g. July 4th week)
JOBLESS_CLAIMS rule DOL weekly initial claims, for the week ended the prior Saturday08:30 rule only: every Thursday that is a session; Wednesday when Thursday is a market holiday (Thanksgiving, Jan 1) or Veterans Day Nov 11 (NYSE trades but DOL is closed)
GDP fredrule BEA GDP estimate; monthly cycle advance → second → third per quarter08:30 FRED id 53; fallback: last Thursday of the month (December: session on/before Dec 23 — BEA pulls year-end releases forward)
PCE fredrule BEA personal income & outlays (PCE price index), for the prior month08:30 FRED id 54; fallback: last Friday of the month (December: session on/before Dec 22)
RETAIL_SALES fredrule Census advance retail sales (MARTS), prior month08:30 FRED id 9; fallback: first session on/after the 15th (real dates cluster 15th–17th)
ADP rule ADP private employment, prior month08:15 the Wednesday before the Employment Situation (using the FRED or rule NFP date), holiday-shifted
DURABLE_GOODS rule Census durable goods orders (advance), prior month08:30 first session on/after the 25th (real dates cluster 25th–27th)
ECI rule Employment Cost Index (quarterly wage inflation; Fed-watched)08:30 last business day of Jan/Apr/Jul/Oct (matches recent years exactly)
JOLTS fred BLS job openings, for the month two back10:00 FRED id 192 only — no fallback rule is emitted because none is reliable enough
ISM_MFG rule ISM Manufacturing PMI, prior month10:00 rule only: 1st business day of the month (this is ISM's schedule)
ISM_SVC rule ISM Services PMI, prior month10:00 rule only: 3rd business day of the month
UMICH_PRELIM / UMICH_FINAL rule U. Michigan consumer sentiment + inflation expectations (current month)10:00 preliminary ~2nd Friday, final ~last Friday (UMich convention; occasionally shifts a week)
CB_CONFIDENCE rule Conference Board consumer confidence (current month)10:00 last Tuesday of the month (the Conference Board's stated schedule)

release_for derivation: CPI/PPI/NFP/PCE = previous month; JOLTS = two months back; GDP = previous quarter, with the estimate label cycling by month within the quarter (Jan releases Q4-advance, Feb Q4-second, Mar Q4-third, Apr Q1-advance, …); claims = week-ending Saturday (release Thursday − 5 days).

Central banks, fiscal & Treasury supply

symtimedate logic
FOMC official 14:00 statement 14:00, press conference 14:30. Embedded FOMC_MEETINGS table in schedules.py — the Fed's published calendar for 2024–2026, all 8 meetings/year, event emitted on day 2; quarterly (Mar/Jun/Sep/Dec) meetings are annotated "includes Summary of Economic Projections (dot plot)". A stderr warning fires for dates in years outside FOMC_YEARS; extend the table when the Fed publishes the next year
FOMC_MINUTES rule 14:00 day 2 + exactly 21 days (the Fed's "three weeks after" practice), holiday-shifted backwards
ECB official 08:15 statement 14:15 CET = 08:15 ET, press conference 08:45 ET. Embedded ECB_DECISIONS (8 decisions/year, 2025–2026 from the ECB's published calendar)
BOJ official ~23:00 the decision lands around midday JST on the meeting's second day = ~23:00–01:30 ET the prior US evening, so the event is emitted on the prior ET date at 23:00 (time approximate by nature — the BOJ has no fixed announcement time). Embedded BOJ_DECISIONS_JST (2025–2026 from the BOJ's published calendar)
JACKSON_HOLE rule 10:00 Fed Chair keynote, Friday morning of the KC Fed symposium — the 4th Friday of August (matches 2024, 2025 and 2026: Aug 27–29); exact speech time is published only days ahead
QRA official 08:30 Treasury quarterly refunding statement (coupon auction sizes). Dates float around the Feb/May/Aug/Nov turn (Jan 28–Feb 5 etc.) — too irregular for a rule, so confirmed dates are embedded in QRA_DATES (2025 – Aug 2026); each statement names the next date
AUCTION_2Y…30Y official 13:00 Treasury coupon auctions (2/3/5/7/10/20/30-year notes & bonds, incl. reopenings; bills/TIPS/FRN excluded). Dates from the keyless TreasuryDirect API: all currently announced auctions (~1–2 weeks forward) plus ~2 years of history. Beyond the announcement window no auction rows exist — the daily sliding-window re-run keeps them filled. Results close 13:00, posted ~13:02

Index events

symtimedate logic
SPY_REBAL_ANNOUNCE rule 17:15 first Friday of Mar/Jun/Sep/Dec — S&P DJI's usual quarterly-rebalance press-release evening. Convention, not a published guarantee
SPY_REBAL_EFFECTIVE official 16:00 third Friday of Mar/Jun/Sep/Dec, holiday-shifted (June 2026 → Thu June 18, Juneteenth). Changes are formally effective before the next open; tracking funds trade at this close. Methodology-fixed
TRIPLE_WITCHING official 16:00 same day as SPY_REBAL_EFFECTIVE (quarterly expiration of index futures/options + stock options)
QQQ_RECON_ANNOUNCE rule 20:00 second Friday of December — Nasdaq's annual reconstitution press release
QQQ_RECON_EFFECTIVE official 16:00 third Friday of December, holiday-shifted; effective at the following open, funds trade at this close
MSCI_REVIEW_ANNOUNCE rule 17:00 ≈23:00 CET, second Tuesday of Feb/May/Aug/Nov — matches recent MSCI review announcements but MSCI only commits to "≥ 9 business days before effective"; treat as ±a few days
MSCI_REVIEW_EFFECTIVE official 16:00 last business day of Feb/May/Aug/Nov (changes effective as of that close)
RUSSELL_PRELIM rule 18:00 preliminary add/delete lists posted after 18:00 ET five Fridays before the June reconstitution (May 22 2026, May 23 2025) — the first tradeable look at the changes
RUSSELL_RECON official 16:00 semi-annual since 2026: June = fourth Friday (holiday-shifted; historically the largest closing auction of the year), December = second Friday starting Dec 11 2026 (per the FTSE Russell schedule update of Nov 2025 — originally announced for November, then moved)

Flows, expirations & elections

symtimedate logic
OPEX official 16:00 monthly options expiration: third Friday (holiday-shifted) of the eight non-quad months; quad months are covered by TRIPLE_WITCHING
VIX_EXP official 09:30 VIX futures/options settlement: 30 days before the next month's standard SPX expiration (third Friday, holiday-adjusted), stepped to the prior session if needed — usually a Wednesday; the SOQ settlement prints off SPX opening rotations
QUARTER_END official 16:00 last session of Mar/Jun/Sep/Dec — pension / target-date rebalance flows and window dressing into the close
US_ELECTION official 20:00 even years, the Tuesday after the first Monday of November (statutory); labeled presidential (year % 4 == 0) or midterm; timestamped at first poll closings, results drive the overnight session
Not implemented (documented gaps) Nasdaq-100 quarterly share/weight adjustments (Mar/Jun/Sep third Fridays); special/ad-hoc index changes (by definition not known ahead of time); mega-cap earnings dates (no reliable keyless calendar — company IR announcements); Fed Chair congressional testimony (dates set only ~1–2 weeks ahead); S&P Global flash PMIs, Empire/Philly Fed, housing data (second-tier); OPEC+ meetings and EIA inventories (commodity-first); Fed bank stress-test results (date announced ad hoc in late June).

5Date sources: the three tiers

Every row carries schedule_source so consumers can filter by confidence.

official

Embedded calendars published far ahead (FOMC, ECB, BOJ, refunding statements), methodology-fixed index/expiration dates, and TreasuryDirect-announced auctions.

Exact; no network needed except auctions.

fred

Exact release dates from the FRED API release/dates endpoint, covering past and future scheduled dates for the BLS/BEA releases. Active only when a key is configured (free, instant: fred.stlouisfed.org/docs/api/api_key) via $FRED_API_KEY or config/fred_api_key.txt (gitignored).

Requests use include_release_dates_with_no_data=true (required to get future dates) over a [year−1, year+1] realtime window, cached 24 h per (release, year).

When the FRED schedule is available it replaces the rule entirely — a date not on the FRED schedule emits nothing, so schedule changes (e.g. shutdown delays) propagate instead of double-printing.

rule

The calendar approximations in §4, used only when FRED is unavailable. Exactness varies: claims/ISM/NFP rules are near-exact; CPI/PPI/GDP/PCE rules are usually within a couple of days; announcement conventions are looser.

Rules cannot know about ad-hoc schedule changes — e.g. the late-2025 government shutdown delayed CPI well past any rule date.

Series used

  • BLS: CUSR0000SA0 (CPI-U SA, m/m), CUUR0000SA0 (CPI-U NSA, y/y), CUSR0000SA0L1E (core CPI SA), WPSFD4 (PPI final demand SA, m/m), WPUFD4 (NSA, y/y), CES0000000001 (nonfarm payrolls level, Δ = monthly gain in thousands), LNS14000000 (unemployment rate).
  • FRED: DFEDTARU/DFEDTARL (target range bounds; the change shows up the day after the decision, which is how held/cut/raised is computed), ECBDFR (ECB deposit facility rate — changes take effect ~a week after the decision, so the comparison window extends 12 days and reports "inconclusive" until past the effective date), ICSA (initial claims, observations are week-ending Saturdays — keyed directly by the event's release_for), A191RL1Q225SBEA (real GDP % q/q SAAR, observation at quarter start), PCEPI/PCEPILFE (PCE price indexes, m/m), RSAFS/RSFSXMV (retail sales, m/m headline and ex-autos), DGORDER (durable goods orders, m/m).
Rejected sources (so nobody re-attempts them) www.bls.gov schedule pages and fred.stlouisfed.org HTML are behind Akamai bot protection (403/hang for non-browser clients) — we deliberately do not fight that; BEA/Census/ISM have no keyless machine-readable schedules; Trading Economics guest API excludes the US; ForexFactory's feed only covers the current week.

Caveats by design
  • Current vintage, not first print. Keyless sources serve today's revised series. For a date summarized shortly after release the value is the released figure; summarizing a year-old NFP date quotes the revised number.
  • Partial data degrades gracefully: CPI/PPI print whichever of m/m / y/y / core are computable (e.g. Nov 2025 CPI shows y/y only because the shutdown cancelled the Oct 2025 index, breaking the m/m base). If nothing is computable, or the event is same-day and the data hasn't landed in the API yet, the fallback text is used.
  • Any summarizer exception is caught, warned to stderr, and falls back — a summary problem never fails the batch date.

8Caching, concurrency, failure behavior

http_cache.cached_text(name, fetch, ttl_hours) backs every network call, storing under cache/ (gitignored, safe to delete):

  • flock per cache entry — the batch runner launches 18 processes at once; the lock makes a cold cache cost one fetch while the other 17 wait and read the result. This is also what keeps the BLS 25-requests/day budget intact.
  • atomic writes (tmp file + os.replace) — no torn reads.
  • TTL + stale-on-error — fresh entries are served from disk; on fetch failure a stale entry is served with a stderr warning, or None if there is none. Validation happens inside the fetch callback, so invalid payloads (rate-limit JSON, HTML error pages) are never written into the cache.

Degradation ladder

failureeffect
no FRED key release dates fall to rule; JOLTS rows absent
FRED API down same as no key (stale cache used if present)
BLS API down / rate-limited CPI/PPI/NFP summaries fall to descriptive text
fredgraph down FOMC/ECB/claims/GDP/PCE/retail/durables summaries fall to descriptive text
TreasuryDirect down AUCTION_* rows absent (stale cache used if present); QRA unaffected
fully offline event list still produced from rules + embedded tables (no auctions); all summaries descriptive

The only nonzero-exit conditions are genuine bugs or filesystem write failures — by design, so a flaky network can't mark batch dates as FAIL.

Maintenance checklist

  • Yearly: extend the embedded calendars — FOMC_MEETINGS, ECB_DECISIONS, BOJ_DECISIONS_JST (stderr warnings appear for uncovered years; all three banks publish 1–2 years ahead).
  • Quarterly-ish: append the next QRA_DATES entry — each refunding statement names the next date (Nov 2026 not yet confirmed as of June 2026).
  • Recommended: configure a FRED key; it upgrades BLS/BEA/Census dates to the published schedule (including future dates) and adds JOLTS.
  • Release ids live in FRED_RELEASES with expected names; a mismatch warns and disables that release rather than emitting wrong dates.

10Adding a new event type

  1. Write a generator in schedules.py returning [Event] only when the event falls exactly on the requested date; wire it into events_for. Set schedule_source honestly (official only for published-calendar or methodology-fixed dates) and always provide a summary_fallback.
  2. If actuals are freely available, add a summarizer in summaries.py and register it in _SUMMARIZERS; put whatever context it needs in Event.ref. Keep fredgraph windows narrow (§6).
  3. Document the sym in README.md and in §4 above.
  4. Spot-check a known past date (summary fills) and a future date (expected), then batch a small range and confirm OK for every day.
